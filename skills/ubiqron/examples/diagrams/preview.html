sequenceDiagram

PlaceOrder

PlaceOrder.sequence.md

Command flow inside the Order context. Shows the repository port (U4), the port-free domain service (U5), the typed exception (U7) and the aggregate raising its event.

sequenceDiagram
    participant Api
    participant H as PlaceOrderHandler
    participant MR as IMerchantRepository
    participant S as OrderDomainService
    participant O as Order
    participant OR as IOrderRepository
    Api->>H: PlaceOrderCommand
    H->>MR: GetById(merchantId)
    MR-->>H: merchant
    H->>O: Order.Create(...)
    H->>S: ProcessOrder(merchant, order)
    alt merchant unavailable
        S-->>H: MerchantUnavailableException
        H-->>Api: rejected
    else merchant available
        S->>O: Place()
        Note over O: raises OrderPlaced
        H->>OR: Add(order)
        H-->>Api: OrderId
    end

stateDiagram-v2

Order lifecycle

Order.state.md

Transition labels are the aggregate's methods. Notes are the invariants that refuse a transition. A state with no transition for a method means that method is refused there.

stateDiagram-v2
    [*] --> Placed : Place()
    Placed --> Rejected : Reject(reason)
    Placed --> Paid : MarkPaid()
    Paid --> Accepted : Accept()
    Paid --> Cancelled : Cancel()
    Accepted --> Delivered : Deliver()
    Accepted --> Cancelled : Cancel()
    Delivered --> [*]
    Rejected --> [*]
    Cancelled --> [*]
    note right of Placed
        ProcessOrder rejects when the merchant is unavailable
    end note
    note right of Delivered
        Cancel is refused after Deliver
    end note

OrderPaymentProcess

OrderPaymentProcess.flow.md

Saga in `Order.Application/Processes/` (U12). It uses the `IPaymentGateway` port, which is the port of the anti-corruption layer towards the Payment Provider. Shows the compensation branch and the retry.

flowchart TD
    A([OrderPlaced]) --> B["Send AuthorizePayment through IPaymentGateway"]
    B --> C{Result}
    C -->|PaymentAuthorized| D["Order.MarkPaid()"]
    D --> E["Publish OrderPaid from Order.Contract"]
    E --> F([Done])
    C -->|PaymentDeclined| G["Order.Reject(PaymentDeclined)"]
    G --> H([Done])
    C -->|Timeout| I{"Attempts below 3?"}
    I -->|yes| B
    I -->|no| G

Order context overview

Order.overview.md

Stereotypes name the building block. Aggregates refer to each other by id only, so the Order to Merchant link is dashed.

classDiagram
    class Order {
        <<AggregateRoot>>
        OrderId Id
        MerchantId MerchantId
        OrderStatus Status
        Money Total
        Place()
        Reject(reason)
        MarkPaid()
        Accept()
        Cancel()
        Deliver()
    }
    class OrderLine {
        <<Entity>>
        ProductId ProductId
        int Quantity
        Money UnitPrice
    }
    class Money {
        <<ValueObject>>
        decimal Amount
        string Currency
    }
    class Merchant {
        <<AggregateRoot>>
        MerchantId Id
        bool IsAvailable
        SetUnavailable()
        SetAvailable()
    }
    class OrderDomainService {
        <<DomainService>>
        ProcessOrder(merchant, order)
    }
    class OrderPlaced {
        <<DomainEvent>>
        OrderId OrderId
        MerchantId MerchantId
    }
    Order *-- OrderLine : lines
    Order --> Money : total
    OrderLine --> Money : unitPrice
    Order ..> Merchant : by MerchantId only
    OrderDomainService ..> Order
    OrderDomainService ..> Merchant
    Order ..> OrderPlaced : raises
